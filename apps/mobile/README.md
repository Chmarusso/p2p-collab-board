# OpenCollab Mobile

This Expo/React Native client uses the same OpenCollab Bare worker as the Electron app. It shares board invites, encrypted board state, profiles, votes, and comments.

```sh
npm install
npm run --workspace @opencollab/mobile bundle:bare
npm run --workspace @opencollab/mobile ios
# or: npm run --workspace @opencollab/mobile android
```

The Pear Mobile runtime requires a native development build; Expo Go is not sufficient. Re-run `bundle:bare` after changing `workers/main.js`.

## Clipboard integration test

With Electron running using `--remote-debugging-port 9222` and an iOS Simulator booted, run:

```sh
npm run test:clipboard
```

The test verifies Electron ↔ macOS clipboard transfer and the simulator pasteboard roundtrip. In the mobile app, use **Paste invitation** on the board join screen to read the simulator pasteboard directly; simulator and macOS pasteboards are separate when controlled with `simctl`.

## P2P OTA updates (iOS)

Release builds update their JavaScript and the embedded Bare worker from the `upgrade`
link in `package.json`, without a new binary. The worker downloads a newer version,
applies it into `Application Support/pear-runtime/ota`, and the app shows "Update
installed"; the next launch boots it (boot control from `pear-runtime-react-native`).
Debug builds always load from Metro, so test OTA with Release builds.

```sh
npm pkg set version=1.0.4 --workspace @opencollab/mobile  # higher than binary + every OTA
npm run --workspace @opencollab/mobile ota                 # → ../opencollab-deploy/mobile-1.0.4
pear stage <upgrade link> ../opencollab-deploy/mobile-1.0.4
pear seed <upgrade link>                                    # keep running somewhere reachable
```

- Only JS/worker changes can ship this way. New native modules, permissions, Pods or
  React Native/Expo upgrades need a new binary; raise `pear.json` `updates.minver` so
  older binaries skip updates they cannot run.
- `package.json` `version` is the OTA version. A new binary must carry a version higher
  than every published OTA (`app.json` `version` → `CFBundleShortVersionString`).
- Updates are checked at launch, immediately during the first 60 s, later after a random
  delay of up to an hour.

## Android release APK

`android/` is generated by `expo prebuild` and not committed. The local
[`plugins/android-release.js`](plugins/android-release.js) config plugin sets what
prebuild would otherwise reset: `minSdk` 29 (required by `react-native-bare-kit`) and
release signing from environment variables. Without those variables, release builds
are signed with the debug key, which is fine for testing but not for publishing.

```sh
cd apps/mobile
npx expo prebuild --platform android --clean --no-install
echo "sdk.dir=$HOME/Library/Android/sdk" > android/local.properties   # macOS
export ANDROID_KEYSTORE_PATH=/path/to/opencollab-release.jks \
  ANDROID_KEYSTORE_PASSWORD=… ANDROID_KEY_ALIAS=opencollab ANDROID_KEY_PASSWORD=…
(cd android && ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a)
# → android/app/build/outputs/apk/release/app-release.apk
```

- The APK is arm64 only: `bundle:bare` builds the worker for `android-arm64`. That
  covers current phones and the arm64 emulator on Apple silicon, not x86 emulators.
- Every release raises `app.json` `expo.android.versionCode`; Android refuses an update
  with a lower or equal code. Keep `expo.version` as the visible version.
- Android only installs an update signed with the same key. Losing the release keystore
  means users must uninstall, which deletes their local boards: back it up offline.
- Android does not receive P2P OTA updates yet (`scripts/ota.js` builds iOS only); each
  release is a new APK.

**Publishing** from this machine, with `gh` logged in. The release script reads the
keystore variables from the shell or from `apps/mobile/keys/release.env` (gitignored, next to
the keystore `keys/opencollab-release.jks`). `git clean -fdx` deletes both, so keep a copy
offline:

```sh
npm run --workspace @opencollab/mobile release:android                # build + draft GitHub release
npm run --workspace @opencollab/mobile release:android -- --no-upload  # build only
```

It refuses to run without the keystore, on a dirty tree, off `main`, out of sync with
GitHub, or when `android-v<version>` already exists. Output lands in `apps/mobile/dist/`
(ignored): the APK and its SHA-256 go to a draft release `android-v<version>`, and the
AAB is for uploading to Google Play by hand. Review the draft on GitHub, then publish.

`.github/workflows/android-release.yml` does the same in CI, run by hand from the Actions
tab, for when the key should live in GitHub secrets (`ANDROID_KEYSTORE_BASE64`,
`ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` in the `release`
environment). Never tag `v*`: that publishes to npm.

**Google Play:** when creating the app, choose to use your existing app signing key and
upload this keystore, so the Play and GitHub builds can update each other. Every upload
needs a higher `versionCode`. The privacy policy is [`PRIVACY.md`](../../PRIVACY.md); give Play its GitHub URL.
Listing text, Data safety and content rating answers, and graphics are in
[`store/`](store/play-listing.md).

**App Store:** listing text, App Privacy, age rating and export compliance answers, and
review notes are in [`store/app-store.md`](store/app-store.md).
